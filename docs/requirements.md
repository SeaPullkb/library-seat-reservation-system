# 需求基线 V1.0

来源：用户提供的已确认毕业设计需求方案及开发任务表。后续业务实现和验收以本文件为准。

## 定位与边界

题目：基于 Spring Boot 的高校图书馆座位预约与签到管理系统的设计与实现。
为 Java 初学者开发一个可运行、可测试、可答辩的 B/S 单体 Web 系统。

- Java 17、Spring Boot 3.x、MyBatis-Plus Boot 3 Starter、MySQL 8。
- Thymeleaf、Bootstrap 5、少量原生 JavaScript、ECharts。
- Spring Security + Session + BCrypt，保留 CSRF，角色为 STUDENT、LIBRARIAN、SUPER_ADMIN。
- Spring @Scheduled 每分钟处理到期记录。仅部署一个应用实例。
- 不做前后端分离，不增加 Redis、Vue、JWT、消息队列或微服务。
- 不做小程序/App、扫码/人脸/NFC/校园卡签到、定位、短信邮件通知、信用分、黑名单、数据导出、硬件感应。
- 点击网页按钮为线上签到，不能宣称验证了真实到馆。
- 所有业务时间来自服务器，时区固定 Asia/Shanghai。

## 固定时段与预约

| 编号 | 时段 | 时间 | 普通签到截止 |
|---|---|---|---|
| 1 | 上午 | 08:00–12:00 | 08:15 |
| 2 | 下午 | 14:00–18:00 | 14:15 |
| 3 | 晚上 | 19:00–22:00 | 19:15 |

- 可预约今天及未来6天，共7个自然日；不能预约过去日期、非法时段或已停止预约的时段。
- 预约时距时段结束至少还有30分钟。只选择固定时段，前端不能指定任意起止时间。
- 学生同日期、同一时段只能占用一个座位；座位同日期、同一时段只能有一个有效占用。
- 可以预约不同日期或不重叠时段。
- 普通签到从时段开始前15分钟开放，截止到时段开始后15分钟。
- 超过普通签到截止才创建的补约，截止为预约成功后10分钟；不延长时段结束时间。
- 普通学生仅可在时段尚未开始且未签到时取消。管理员可取消未签到违规预约并填写原因。
- 超时未签到的预约释放后允许补约，历史记录保留。
- 已签到过的座位，即使提前签退，当前日期和时段也不再开放；该学生当前时段也不能重新预约。

## 状态与并发

| 状态 | 说明 | 是否锁定该日期时段 |
|---|---|---|
| PENDING | 待签到 | 未过期时是 |
| USING | 使用中 | 是 |
| COMPLETED | 已签到并完成 | 是 |
| CANCELLED | 未签到时取消 | 否 |
| EXPIRED | 未签到超时释放 | 否 |

签到成功记录 checkin_at；主动签退记录 checkout_at 并转 COMPLETED；时段结束自动完成时记录时段结束时间。
签到、签退、取消都需要校验当前状态、身份和服务器时间；重复提交不得重复变更。

预约创建应在事务中按学生→阅览室→座位→预约记录的统一顺序取锁，验证用户/阅览室/座位启用状态、日期时段及冲突。
事务内处理尚未由定时任务释放的过期记录，再检查学生与座位的有效记录和已签到记录。
实现时先按当前时间做双向冲突检查，通过后仅更新已锁目标座位对应的过期PENDING，再创建新记录；不跨座位批量更新过期状态。对学生在其他座位上的已过期记录，按时间认定无效，后续由释放任务处理。
不能只判断 PENDING，也不能依赖定时任务及时执行。定时任务和请求的更新必须包含原状态条件。
不得对全部历史记录的 seat_id + reserve_date + time_slot 建唯一约束，因为释放后同一时段需要再次插入。

预约创建、学生取消、签到、签退与逐条到期处理使用独立READ_COMMITTED事务，以便等待行锁后读到上一事务的提交结果。InnoDB在修改带索引的预约状态时可能因外键检查取得隐式用户行锁；仅对确认的死锁1213完整回滚后重试，最多三次尝试，其他数据库错误继续失败。每次重试重新取得锁并校验身份、状态与服务器时间，不重复使用旧检查结果。

取消操作要求时段尚未开始、PENDING、未签到且未过签到截止，记录取消人、原因和时间。重复取消已取消记录不重复更新时间。个人查询按登录身份隔离，支持五种状态筛选和每页20条；过期但尚未持久化释放的PENDING按实际截止显示/筛选为EXPIRED，GET查询不修改数据库。

签到截止时刻有效，超过才过期；直接签到发现超时也须先提交EXPIRED，再反馈业务失败。时段结束的USING按COMPLETED显示和筛选；实际签到、签退时间只展示已保存值。调度启动时补处理，之后每次执行完等待60秒扫描，每批最多200个ID、逐条独立事务。系统清理不因所有者禁用或角色变化跳过记录；单条失败不影响其他记录，留待下轮重试。重复签到、签退及清理不得覆盖原实际时间。

seat.status 只表示管理员设置的启用或停用；日期时段占用状态由预约记录计算。

维护操作从阅览室锁开始，再取所属座位锁。停用检查将签到截止尚未过去的PENDING及使用时段未结束的USING视为有效预约；COMPLETED仍保护预约时段，但不阻止管理员停用。已超期但尚未由定时任务更新的PENDING不阻止停用，历史记录保持原样供后续释放流程处理。阅览室停用不批量改写座位自身启用状态，重新启用后恢复原有配置。

## 四张核心业务表

完整字段、类型、约束以 `src/main/resources/db/schema.sql` 为准。

- user：账号（唯一）、BCrypt密码、姓名、班级、手机号、角色、启用状态、创建时间。
- reading_room：名称、位置、介绍、启用状态、创建时间；容量按启用座位数计算，不重复保存。
- seat：阅览室ID、编号、启用状态、创建时间；同阅览室内编号唯一。
- reserve_record：学生ID、座位ID、日期、时段、五种状态、本次签到截止、实际签到/签退/释放/取消时间、取消人/原因、创建及更新时间。
- 预约表按座位/日期/时段/状态、用户/日期/时段/状态建立查询索引，外键不级联删除历史数据。
- 有历史关联的座位停用替代删除；无关联记录才可物理删除。
- 停用存在未来有效预约的座位前，必须先处理预约；停用阅览室也须检查关联座位与预约。
- 禁用存在 PENDING 或 USING 预约的用户前，必须先处理预约。

## 角色与功能

学生：注册、登录退出、个人信息与密码修改、阅览室浏览、按日期时段选座、预约、我的预约筛选、取消、签到、签退和补约。只能操作自己的预约，后端从登录身份取得用户ID。

图书馆管理员：阅览室及座位管理、预约条件查询与分页、违规未签到预约取消及原因记录、签到情况查询、数据统计。

超级管理员：继承管理员权限；查询用户、新建管理员、修改角色、重置密码、启禁用账号。普通注册入口永远只能创建 STUDENT。首次初始化创建超级管理员。

## 统计口径

- 每日预约人数：按使用日期去重学生，不计 CANCELLED。
- 每日预约次数：按使用日期统计提交的全部记录数。
- 阅览室预约率：指定日期时段锁定的不同座位数 / 启用座位数。
- 签到率：已过签到截止的非取消预约中，实际有 checkin_at 的记录比例。
- 超时释放次数：指定日期 EXPIRED 记录数。
- 图表展示最近7天预约人数、所选日期时段各阅览室预约率；不做复杂报表。
